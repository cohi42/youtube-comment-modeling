# 문제 정의

## 출발점

초기 가설은 단순했다.

> 좋아요를 많이 받은 댓글을 학습하면, 좋아요를 많이 받을 댓글을 생성할 수 있지 않을까?

YouTube Shorts는 이 가설을 실험하기 좋은 플랫폼처럼 보였다. 영상과 오디오가 함께 존재하고, 댓글에는 좋아요 수라는 명확한 engagement 지표가 붙어 있기 때문이다.

하지만 실제로 데이터를 들여다보면 `댓글 좋아요 수 = 댓글 품질`이라는 가정은 너무 단순했다.

## 왜 어려운 문제였나

YouTube 댓글 좋아요 수는 댓글 자체의 품질뿐 아니라 여러 외부 요인의 영향을 받는다.

- 영상 조회수가 높을수록 댓글이 좋아요를 받을 기회가 커진다.
- 업로드 직후 달린 댓글은 더 오래 노출된다.
- 초반 좋아요를 받은 댓글은 상단에 노출되고, 다시 더 많은 좋아요를 받는다.
- API로는 댓글의 실제 노출량, 노출 위치 변화, 추천 알고리즘 영향을 볼 수 없다.
- "좋은 댓글"은 사실성, 맥락성, 공감, 유머, 말투가 섞인 복합적인 개념이다.

따라서 이 프로젝트의 실제 문제는 댓글 생성 자체보다 앞단에 있었다.

> 불완전한 engagement signal을 어떻게 학습 가능한 preference label로 근사할 것인가?

## 재정의한 문제

이 프로젝트는 다음과 같은 형태로 문제를 다시 정의했다.

- 입력: YouTube Shorts 영상, 오디오, 메타데이터, 댓글 데이터
- 원본 신호: 댓글 좋아요 수
- 보정 변수: 영상 조회수, 댓글 작성 시점, 영상-댓글 관련성
- 목표: raw like count가 아니라, 편향을 보정한 preference proxy가 높은 댓글 후보를 선별
- 후속 실험: 선별한 댓글 후보로 멀티모달 댓글 생성 모델을 SFT/LoRA 방식으로 학습

## 이 정의의 의미

이 문제 정의는 완벽하지 않다. 실제 댓글 노출량을 알 수 없고, 플랫폼 알고리즘도 관측할 수 없기 때문이다.

하지만 공개 API와 제한된 연구 환경에서 접근 가능한 변수만으로 사용자 선호를 근사하려면, 단순 좋아요 수를 그대로 쓰는 것보다 다음이 더 설득력 있다고 판단했다.

```text
Raw Like Count
  -> View-count correction
  -> Time-decay correction
  -> Relevance filtering
  -> Preference proxy score
```

즉 이 프로젝트는 "좋아요가 높은 댓글 생성"을 바로 학습하려 한 것이 아니라, 먼저 "좋아요가 높은 이유"를 분해하고, 그중 댓글 내용에 가까운 신호를 남기려 한 시도였다.

## 포트폴리오 관점의 핵심

이 프로젝트의 가치는 모델 성능 하나로 설명하기 어렵다.

더 중요한 점은 다음과 같다.

- 나이브한 가설에서 출발해, label 자체가 불안정하다는 문제를 발견했다.
- 모델 학습 전에 데이터와 평가 기준을 다시 설계해야 한다는 것을 경험했다.
- NLP/생성 과제에서 evaluation과 proxy label 설계가 핵심 병목이 될 수 있음을 배웠다.
- 실패한 실험을 단순히 감추지 않고, 왜 실패했는지 분석 가능한 형태로 정리했다.
